# Landslide ver3 작업 기준

산사태 발생기록, AWS·ASOS 강우, 5m DEM의 경사 정보를 행정구역 단위로 결합하여 머신러닝 학습자료를 만든다. 강우 이벤트와 발생기간을 연결하고, 이벤트 종료일을 포함한 이전 n일 누적강우를 계산한다. 2026-10-07 현재 01~05 계산과 06 발생 기준표·강우 보유 현황 점검을 완료했다. 비교표본 무작위 추출·추가 다운로드·모델 학습은 미수행이다.

- [AGENTS.md](../AGENTS.md), [기초자료 설명](base/inputs.txt).
- [기존 작업 정리](../ver2/codesleft.md), [기존 후속 단계 계획](../ver2/stages13plus.md): 참고용이다. 과거 계획·완료 상태를 ver3에 그대로 적용하지 않는다.

│  ├─ base/                   확보된 기초 입력, 읽기 전용 취급

│  │  ├─ boundaries/
│  │  └─ DEM/5m/              외부 DEM을 가리키는 Junction
│  ├─ codes/<단계번호>_<작업명>/              각 단계 코드
│  │  └─ (공통 I/O는 codes/common.py)
│  ├─ config/                 공통 경로·분석 설정
│  ├─ output/<코드번호>/      해당 단계의 가공 결과
│  ├─ log/<코드번호>/         실행·API·QC·오류 기록

`codes`, `config`, `output`, `log`, `final`은 필요할 때 생성한다. 빈 폴더나 문서를 미리 대량 생성하지 않는다. 코드 `01_*.py` 또는 `01_*.ipynb`의 결과는 `ver3/output/01/`, 로그는 `ver3/log/01/`에 저장한다.

- `ver2/`, 기존 `raw/`, 외부 원본, `base/` 입력을 후속 분석에서 수정·삭제하지 않는다. 입력 갱신이 필요하면 출처와 변경 범위를 먼저 확인한다.
- 이전 단계 output은 읽기 전용 입력이다. 후속 단계가 덮어쓰지 않는다.
- 실행마다 필요 없는 결과 복사본을 만들지 않는다. 기존 결과 교체가 필요하면 대상·복구 방법·사용자 승인 범위를 확인한다.
- Notebook은 다른 커널의 변수 없이 파일 입력만으로 독립 실행되어야 한다.
- 실제 완료 변경과 앞으로 할 계획을 구분하여 루트 `workflow/framework/`의 텍스트 이력에 기록한다.

## 4. 필수 강우 저장·로드 규칙

**새로 확보한 AWS·ASOS 관측 강우는 RAIN_DATAS의 기존 형식에 맞는 Parquet으로 추가하고, 분석에서도 그 파일을 직접 읽는다.** ver3의 base에 관측 강우 원본을 중복 보관하거나 INT를 기본 입력으로 사용하지 않는다.

```text
/data/RAIN_DATAS\지상관측\
  AWS\hourly\YYYY\MM\DD\data_YYYYMMDD.parquet
  ASOS\hourly\YYYY\MM\DD\data_YYYYMMDD.parquet
```

| 열 | 형식·의미 |
|---|---|
| `STN` | int64, 관측소 번호 |
| `time_start` | timestamp, KST 구간 시작 |
| `time_end` | timestamp, KST 구간 종료 |
| `RN_1H` | float64, 해당 1시간 강우량(mm), 결측은 null |

- 구간은 **`[time_start, time_end)`**, 길이는 1시간이다. 현재 저장 형식은 timezone 정보가 없는 KST timestamp다. UTC로 오해하지 않는다.
- 폴더와 파일 날짜는 **KST `time_start` 날짜**다. API 종료시각과 구간 시작시각의 차이를 확인한 뒤 변환하며, 이미 변환된 자료에 다시 1시간을 빼지 않는다.
- 실제 무강우 `0`과 결측을 구분한다. 음수 결측 코드·비유한 값은 출처 규칙을 확인하여 null로 정규화하고 사유를 기록한다. 결측을 자동으로 0 또는 추정값으로 채우지 않는다.
- 전체 식별키는 `(network, STN, time_start, time_end)`다. AWS와 ASOS의 동일 관측소 번호를 무조건 같은 관측소로 보거나 합친 뒤 중복 제거하지 않는다.
- 기존 파일의 열·자료형·Parquet 메타데이터를 먼저 확인한다. timezone, rain_unit, partition_by, interval 등 기존 규약을 보존한다.

### 새 자료를 추가할 때

1. 요청 범위의 관측망·관측소·기간과 출처를 확인한다. 수집이 필요한 경우 허용된 API·원자료와 권한을 사용한다.
2. 원자료는 보존하고 표준 4개 열로 변환한다. 원본 QC 정보와 수집 출처는 별도 출처 기록에 남긴다.
3. 대상 날짜의 기존 Parquet을 읽어 키를 비교한다. 동일 값 중복은 제거하되, 동일 키에 값이 다르면 충돌로 기록하고 자동 확정하지 않는다.
4. 임시 파일에서 자료형, 시간구간, 날짜 분할, 중복, 결측, 행 수를 검증한 뒤 안전하게 반영한다. 기존 관측값을 조용히 덮어쓰거나 날짜 파일 전체를 신규분만으로 교체하지 않는다.
5. 기존 `index.parquet` 및 해당 관측망의 출처 목록을 기존 항목 보존 방식으로 갱신한다. 공통 index 열은 `kind, table, date, rows, stations, missing, file`이다. `file`은 관측망 폴더 기준 상대경로를 사용한다.
6. ASOS의 `sources.parquet`, AWS의 기존 `index.xlsx` 출처 시트 등 **실제 존재하는 관측망별 관리 형식**을 따른다. 모든 관측망에 같은 관리 파일이 있다고 가정하지 않는다. 수집·변환·충돌·QC 로그는 `ver3/log/<코드번호>/`에 남긴다.

공유 저장소에 쓰려면 환경의 실제 쓰기 권한도 충족해야 한다. 권한 오류를 경로 우회로 해결하지 않는다. `RAIN_DATAS` 안의 원자료 보관 폴더는 수정하지 않는다.

### 분석에서 불러올 때

경로는 설정에서 관리하고 필요한 기간·관측소·열만 선택하여 읽는다. index와 실제 파일을 함께 확인하고, 없는 날짜·관측소 및 결측 구간을 명시한다. 두 관측망의 중복 처리·우선순위는 명시적 규칙으로 적용하고 출처를 유지한다.

통합/QC·복원 강우, 일강우, 이벤트, 누적량, 학습 특징은 **`ver3/output/<코드번호>/`**에 저장한다. 추정·복원값은 관측값과 구분한다. 분석 파생물을 관측 원본으로 RAIN_DATAS에 되돌려 넣지 않는다.

### 시간과 이벤트

- 등급화 대상은 **산사태 발생시점의 상세도(발생기간 폭)**다. 원래 등급과 시작·종료 범위를 보존한다. 최대 강우일을 실제 발생일로 대체하지 않는다.
- 기존 기준인 시간강우 `1 mm 이상` WET, 연속 DRY 12시간 분리, 연속 UNKNOWN 12시간 분리를 우선 유지하되 설정으로 변경 가능하게 만든다. 구현 전 보관 코드와 정의를 대조한다.
- 결측을 DRY로 취급하지 않는다. 이벤트 내부의 짧은 결측도 유효성 표시에 남긴다. 1mm 미만 관측량도 누적 계산에서 임의로 버리지 않는다.
- 발생기간과 겹치는 이벤트가 여러 개면 후보를 유지한다. 가장 큰 강우를 자동으로 원인 이벤트로 확정하지 않는다.
- 마지막 강우 구간의 종료시각과 12시간 무강우 이후의 종료 확인시각을 구분한다. 자정의 배타적 종료시각을 어느 날짜에 귀속할지 명시한다.
- 누적은 **이벤트 종료일을 포함한 이전 n일**이다. 일강우의 종료일 전체 합계는 정확한 이벤트 종료시각 이후의 강우를 포함할 수 있으므로 시각 기준 합계와 구분한다.
- 이벤트 종료까지 관측한 강우를 쓰는 설계는 사후 분석이다. 이를 발생 전 조기경보 성능으로 해석하지 않는다.

### 공간과 경사

분석 단위는 행정구역을 기준으로 하되, 현재 보유 경계의 법정동·리와 행정동의 차이, 경계 기준연도를 먼저 확정한다. 코드·명칭만으로 불확실한 위치를 강제 배정하지 않는다.

DEM은 필요한 영역만 읽는다. 수평·높이 단위, 좌표계, NoData, 타일 경계와 확보율을 확인하고 경사를 도 단위로 계산한다. 경사 분포와 임계각 이상 면적·비율의 분모는 유효 DEM 면적으로 명시하고, 전체 구역 면적 대비 확보율도 함께 남긴다.

### 비교표본과 학습

- 무작위 비교표본은 발생표본과 **같은 기준일**, 강우·공간자료가 유효한 후보 지역에서 뽑는다. 낮은 강우·완만한 경사만 선택하여 쉬운 음성표본을 만들지 않는다.
- 기록이 없다는 것은 확정 미발생이 아니다. 원자료 상태는 `NO_REPORTED_LANDSLIDE`로 남기고 모델의 0 라벨은 가정임을 구분한다.
- 알려진 산사태의 넓은 발생기간·불확실한 위치와 충돌하는 후보는 제외하거나 REVIEW로 남긴다. 표본 풀·seed·비율·제외 규칙을 기록한다.
- 같은 공간·기준일의 중복 사건은 출처 사건 ID를 유지하며 집계한다. 다중 후보를 독립 사건으로 세지 않는다.
- 동일 사건의 후보, 공유 강우 이벤트·관측소, 겹치는 누적기간에서 생길 정보 누출을 검토하여 그룹·시간·지역 단위로 분리한다. ver2의 분할을 그대로 재사용하지 않는다.
- 발생기간 상세도나 확정 여부처럼 정답에서 얻은 정보는 일반 예측 입력에 넣지 않는다. 불확실 사례는 REVIEW/UNRESOLVED/AMBIGUOUS로 유지한다.

누적기간은 2026-10-07 사용자 지시로 **1~15일 각각**으로 확정했다. 경계 단위·기준연도, 최종 공간별 강우 집계, 향후 결측 허용·복원 정책, 경사 임계각, 다중 이벤트 후보의 학습 기여 방식, 비교표본 비율·seed, 검증 분할은 추가 확인 대상이다. 예시 수치를 확정 설정으로 사용하지 않는다. 이 결정 없이 가능한 입력·메타데이터 점검은 진행할 수 있다.

- 강우 저장은 `[time_start,time_end)`다. 정확한 발생시각의 이벤트 연결은 기존 ver2의 `RAIN_START < 발생시각 <= 마지막 WET 종료시각` 기준을 유지한다.

- 핵심 결과는 `output/04/full/landslide_end_date_features.parquet`이다. 사건×겹침 후보 한 행이며, 공간 최종 집계·미보고 비교표본·DEM·모델 학습은 아직 포함하지 않는다. 후보 수는 독립 사건 수가 아니다.

### 05단계 준비 상태·진행 확인 (2026-10-07 갱신)

사용자가 DEM 표고 단위를 m로 확인하여 `vertical_scale_to_m=1.0`과 사용자 확인 근거를 설정했다. 사용자 지시로 실제 계산은 실행하지 않았다. 이전 높이 단위 대기 기록은 당시 실행 이력으로 보존한다.

실행 중 콘솔에 현재 단계·건수·단계 진행률·전체 경과·현재 단계 예상 남은 시간·처리 항목을 표시한다. `log/05/<mode>/progress.html`은 실행 중 5초마다 새로고침되며 같은 폴더 `progress.json`에 상태를 기록한다. 갱신은 보통 2초 간격이며 개별 파일 읽기/블록 계산이 끝나야 갱신될 수 있다. ETA는 충분한 처리량이 쌓인 뒤 추정하며 전체 파이프라인 시간이 아닌 현재 단계 시간이다. 오류·사용자 중단은 FAILED/CANCELLED로 표시한다. 진행률은 재개 기능을 의미하지 않는다.

경사각은 원래 DEM 좌표계·5m·float32 도 단위 `slope_degrees.tif`(압축 sparse BigTIFF, NoData=-9999)로 저장한다. 행정구역 특징은 `admin_slope_features.parquet`, 분포는 `slope_histogram_1deg.parquet`, 계산 대상은 `processed_units.parquet`, 타일 목록은 `dem_tile_index.parquet`로 저장한다. 분석 결과·summary.html은 output/05/<mode>, 진행·실행·오류 기록은 log/05/<mode>에 둔다. 별도 PNG는 기본 생성하지 않는다.
